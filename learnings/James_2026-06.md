## Docker compose file - giving container's own internal .venv
your compose file mounts your local backend folder over /app inside the container when we run docker compose up.

volumes:
  - ./backend:/app
If the Docker image created /app/.venv during build, that bind mount can hide it if the local backend doesn't have .venv

Adding this:

volumes:
  - ./backend:/app
  - /app/.venv
gives the container its own internal .venv, so your local files still mount into /app, but the container’s installed Python packages do not get covered up.

## How SQLAlchemy(Async) and Alembic(Sync) works together
Process:
FastAPI app code
  uses async SQLAlchemy
  uses asyncpg
  uses await

Alembic migration files
  use sync-style functions
  use op.create_table(...)
  do not use await

env.py
  connects to DB asynchronously
  hands Alembic a sync-compatible connection
